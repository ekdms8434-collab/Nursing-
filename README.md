# NURSING+ 간호교육 성과관리

관리자 대시보드와 학생용 My Nursing Career Hub를 제공하는 HTML 데모입니다. 기존 데모 UI는 `index.html`에 포함되어 설치 없이 실행됩니다. **엑셀 대조·Gemini 분석** 기능만 별도 Node.js 로컬 백엔드와 패키지 설치가 필요합니다.

## 실행

1. `index.html`을 Microsoft Edge 또는 Chrome에서 엽니다.
2. 상단 **학생 화면 보기 / 관리자 화면 보기** 또는 왼쪽 메뉴로 화면을 전환합니다.
3. 보고서 출력 버튼을 누른 뒤 브라우저 인쇄 창에서 **PDF로 저장**을 선택합니다.

기존 데모는 사용자가 직접 파일을 열면 됩니다. VS Code 확장·빌드는 필요하지 않습니다. 엑셀·Gemini 기능은 아래 서버 실행 절차를 따르세요. 파일 URL과 HTTP 주소(호스트·포트 포함)는 브라우저 저장 영역이 서로 달라 기존 프로그램·예산 기록이 자동으로 옮겨지지 않습니다. 기존 파일 화면의 저장 자료는 삭제하거나 덮어쓰지 않습니다.

## 엑셀 대조 · Gemini 분석 실행

1. Node.js 22 이상을 설치하고 프로젝트 루트 터미널에서 `npm install`을 실행합니다.
2. `.env.example`을 `.env`로 복사하고 `GEMINI_API_KEY`에 기관에서 승인한 Gemini API 키를 설정합니다. 키를 HTML·소스 코드·채팅에 넣지 마세요. `.env`는 Git에서 제외됩니다. 키 없이도 로컬 엑셀 대조는 가능합니다.
3. 기본 모델은 `gemini-2.5-flash`이며 필요하면 서버의 `GEMINI_MODEL`을 사용 가능한 모델 ID로 변경합니다. Gemini API 이용 약관·데이터 처리·요금·모델 접근 권한은 기관이 확인해야 합니다.
4. `npm start`를 실행한 뒤 `http://127.0.0.1:3000`으로 접속합니다. `PORT`로 포트를 변경할 수 있습니다. 서버는 이 컴퓨터의 루프백에만 바인딩되며 기존 HTML 파일도 같은 서버에서 제공합니다. 종료는 실행 터미널의 Ctrl+C입니다.
5. **취업 연관성 분석 → 엑셀 대조 · Gemini 분석**에서 두 XLSX 파일을 불러옵니다.
6. 파일별 시트·학번 열을 지정하고 명단의 과정명·참석/이수 상태 열, 취업현황의 결과 분류·졸업 코호트 열을 지정합니다. **선택 열의 상태값·과정값 확인** 후 원본 과정을 표준 과목군에 연결합니다. 같은 과목군으로 연결한 과정은 통합됩니다.
7. 포함할 참석/이수 상태값과 취업 결과값을 정확히 입력합니다(쉼표 구분). 미지정·공백 취업 결과는 미확인으로 집계하고 건수를 알립니다. 취업상태와 병원 유형이 분리되어 있다면 상급종합병원/종합병원/기타 취업/미취업/미확인이 구분되는 한 열로 먼저 정리하세요. 취업자만 있는 파일로는 분석하지 마세요.
8. **학번 대조 · 로컬 통계 분석**으로 중복·누락·매칭 진단, 전체/코호트/과목군/조합 집계와 취업률을 확인합니다. 취업률 분모는 취업 현황 확인 인원입니다. 명단에 없는 학생은 ‘기록 없음’이지 미이수가 확정된 것은 아닙니다.
9. **Gemini 전송 집계 미리보기**를 검토하고 기관의 외부 전송 승인을 확인한 뒤 **Gemini 해석 요청**을 누릅니다. 숫자는 로컬 코드가 계산하고 AI는 전달받은 집계만 해석합니다. 키 미설정·할당량·시간 초과·응답 차단 등은 오류로 알리며 가짜 응답으로 대체하지 않습니다.
10. 상단 **분석 보고서 인쇄 / PDF 저장**은 현재 엑셀 결과와 AI 해석 초안을 출력합니다. 명단/열/상태값 수정 시 이전 결과·동의·AI 해석은 무효화되므로 다시 분석해야 합니다.

### 파일 준비와 개인정보 처리 범위

- XLSX만 지원합니다(XLS·CSV·PDF 미지원). 파일당 한 시트, 첫 행은 제목, 파일당 8MB·전체 20,000행·최대 20시트·시트당 80열·셀당 1,000자입니다. 수식은 값으로 바꾸고 분석에 불필요한 개인정보 열은 삭제한 사본을 권장합니다. 압축 해제 크기도 40MB로 제한합니다.
- **학번은 텍스트로 저장**하세요. 공백 제거·유니코드 표준화 후 정확히 대조하며, 앞자리 0의 추정 복원이나 이름으로 유사 매칭하지 않습니다. 졸업생 학번 중복·누락은 차단하고 참석/이수 명단 중복은 학번+원본 과정 기준으로 제거합니다. 과목군별 복수 회차 이수는 학생 1명으로 집계합니다.
- 졸업 코호트는 최대 24종입니다. 과정 열이 없으면 단일 과정명을 입력할 수 있습니다. 상태 열이 없으면 확정된 참석/이수 명단임을 확인해야 합니다. 참석과 이수는 자동으로 동일시하지 않으며 사용자가 지정한 상태만 포함합니다.
- 원본은 **이 컴퓨터의 로컬 서버 메모리**에서만 읽고 파일·DB·브라우저 저장소에 저장하지 않습니다. 최대 6개 파일·10개 결과, 20분 만료입니다. **업로드·분석 자료 삭제**로 서버와 화면 자료를 제거할 수 있습니다. 서버 종료 시 메모리 자료도 사라집니다. 화면에 이미 표시된 집계는 새로고침·삭제 전까지 남을 수 있습니다.
- Gemini에는 서버가 만든 보호 집계만 보냅니다. 학번·이름·연락처·원본 과정명·코호트·파일·열 제목은 보내지 않습니다. 비영 셀이 5명 미만이면 해당 집계는 제외합니다. 여러 겹치는 집계의 교차 추론을 줄이기 위해 전체 및 안전한 과정 분할 **최대 1개**만 전송합니다. 조합/코호트별 상세 수치는 로컬에서만 제공하며 AI가 이를 분석했다고 주장하지 않습니다. 안전한 전체·비교 집계가 없으면 AI 전송을 차단합니다.
- 이 보호 규칙은 완전한 익명성을 보장하는 인증 체계가 아닙니다. 실제 자료·외부 전송은 기관 승인, 개인정보 처리 검토, Gemini 측 데이터 처리 정책 확인이 필요합니다. Gemini에 보낸 집계와 응답에는 제공사 정책이 적용되며 이 앱에서 회수할 수 없습니다.
- 실제 취업 성과의 인과관계·유의성·개인 취업 가능성을 산정하지 않습니다. 참여 시점·졸업 시점의 선후관계는 입력 파일에서 검토해야 합니다. 성적·경력·자기선택·누락 등 교란 요인이 있으며 AI 해석은 검토용 초안입니다. 생성 내용은 일반 텍스트로 표시·출력합니다.
- 이 서버는 기관 운영용 인증·권한·감사·TLS·공유 서버가 아닙니다. 인터넷/학내망에 포워딩하거나 노출하지 마세요. 기존 학생·수강·예산 화면은 여전히 데모입니다. 원본 엑셀은 승인된 로컬 분석 경로에서만 사용하세요.

### 검증

`npm test`로 가상 엑셀·학번 대조·집계 보호·로컬 HTTP·모의 Gemini 응답을 검증합니다. 실제 API 키 없이 실행하며 테스트는 Gemini에 연결하지 않습니다. 실제 모델 호출은 사용자의 키·기관 승인·요금 확인 후 별도로 검증해야 합니다.

## 구현 기능

### 부서 관리자

- 글로벌 KPI, 목표 대비 상태 표시, 7개 과목군 선택 필터.
- 성과 대시보드의 **운영 중인 비교과** 옆에 **예산 집행률** 요약: 모든 프로그램·회차의 총 지출 ÷ 총 배정 예산을 표시하며, 총 지출·예산 금액도 함께 표시합니다. 직접 등록한 예산 자료 기준으로 예산 변경 시 갱신되고 수입·데모 결제액은 계산에서 제외됩니다. 배정 예산이 0원이면 ‘산정 불가’, 총 지출이 총예산을 넘으면 ‘예산 초과’로 표시합니다. 개별 회차 초과 여부는 예산 탭에서 확인하세요.
- SVG 방사형 차트, 수강률·이수율·사전/사후 역량·만족도 그래프.
- 2025년 8월 / 2026년 2월 졸업 코호트별 취업 히트맵.
- 왼쪽 **취업 연관성 분석** 또는 대시보드 **상세 분석 보기**에서 독립된 상세 화면으로 이동합니다. 코호트·이수 기준 과정·취업 기관 유형을 선택한 뒤 **분석 적용**으로 지표·차트·집계표를 함께 갱신하고 **조건 초기화**로 전체 조건으로 돌아갑니다.
- 상세 분석은 개인 식별 정보 없는 별도 가상 졸업생 220건을 사용하며 대시보드 고정 집계·로컬 수강 기록과 연결되지 않습니다. 과정은 이수/미이수 비교 기준, 기관 유형은 취업률 분자 기준입니다. 취업 현황 확인 인원이 분모이며 미확인 인원은 제외해 별도로 표시합니다. 상급종합병원 취업 비중만 전체 취업자 대비 구성비로 유지합니다. 기준일은 2026-03-31(가상)입니다.
- 상세 화면의 과정별 비교 그래프·조합 히트맵에서 그룹명을 누르면 하단 집계표를 해당 그룹으로 좁힙니다. **전체 그룹 보기**로 복원하며, **분석 보고서 인쇄 / PDF 저장**은 적용 조건의 전체 그룹·지표·집계 기준을 출력합니다. 필터 편집 중 미적용한 조건은 출력에 반영하지 않습니다. 그룹 중복 합산 금지, 확인 인원 10명 미만 소수 표본, %p 차이의 인과적 해석 금지를 안내합니다.
- 상세 분석 조건과 그룹 선택은 화면 이동 중에는 유지되고 새로고침하면 초기화됩니다. 가상 분석 자료와 필터는 로컬 수강·예산 저장 자료를 수정하지 않습니다.
- 인원·비율을 함께 표시하는 히트맵과 비교 막대, 규칙 기반 인사이트 토글.
- 프로그램 개설과 학생 모집 목록 반영.
- 별도 **비교과 운영 관리** 화면에서 교육 선택 및 교육별 신청자 명단 조회.
- 신청자 이름·학번·전화번호·이메일·수강 승인상태 확인, 신청·대기·승인 인원 요약 및 개별 수강 승인.
- 교육별 명단에서 출석 체크와 개별 이수 처리·취소, 이수일·이수상태·이수 완료 인원 확인.
- 데모 수강·결제 목록과 출석 확인 후 이수 승인, 완료 기록 취소.
- 대시보드의 **행정 처리 & CQI 자동화** 옆 독립 카드 **예산 · 집행 현황**에서 프로그램별 전체 회차의 배정 예산·지출·잔액·집행률을 항상 요약 조회합니다. 모바일에서는 행정 카드 아래에 표시됩니다. **상세 관리**를 누르면 해당 프로그램의 예산 관리 화면(전체 합계)으로 이동합니다. 예산 변경 내용은 요약에도 반영됩니다. 내부 예산 탭이나 팝업창이 아닌 별도 카드입니다.
- **예산 · 집행 관리**에서 프로그램 내 예산 회차 등록·정보 수정, 회차별 독립 예산·항목 배정·수입·지출 관리, 프로그램 합계 및 범위별 보고서 출력.
- 7개 과목군 성과와 예시 개선·환류 계획을 포함한 CQI 출력 초안.

### 학생

- 이수 내역에 연동되는 6대 역량 참고 점수와 학년별 권장 로드맵.
- 과정별 모집 카드, 정원 확인, 중복 신청 방지, 데모 결제.
- 신청 시 가상 계정의 이름·학번과 연락처 입력, 관리자 수강 승인상태 확인.
- 관리자 승인 내역과 마일리지, 데모 이수 확인서 출력.
- 태그 기반 실습일지 저장·삭제.
- 이수 기록과 태그가 일치하는 실습일지를 연결한 편집형 STAR 가이드.
- 지원 병원·문항 유형 선택, 포트폴리오 초안 저장 및 출력.

- 모바일 모집 카드 가로 스와이프.

## 교육 개설 및 신청자 관리

1. 왼쪽 **비교과 운영 관리** 메뉴에서 **프로그램 개설**을 선택합니다.
2. 예를 들어 **투약의 모든 것**이라는 이름으로 교육일·수강 정원·대기자 정원·교육비·과목군·대상을 입력해 개설합니다. 수강 정원은 1~500명, 대기자 정원은 0~500명의 정수입니다. 개설된 교육이 자동 선택됩니다.
3. **학생 화면 보기**에서 해당 교육의 **신청하기**를 누릅니다. 이름·학번은 고정된 가상 계정이고, 전화번호·이메일은 가상 정보로 입력할 수 있습니다.
4. 수강 정원 내 데모 신청을 접수하면 **수강 승인 대기**가 됩니다. 이 인원도 수강 정원에 포함하며 중복 신청을 막습니다. 수강 정원이 차면 설정한 대기자 정원까지만 **대기 신청**을 받습니다. 대기자 정원이 0명이거나 대기 한도까지 차면 접수가 마감됩니다.
5. **비교과 운영 관리 → 교육 선택**에서 해당 교육을 선택하면 그 교육의 신청자만 표시됩니다. 이름·학번·전화번호·이메일·수강 승인상태를 확인하고 **수강 승인**을 누릅니다.
6. 수강 승인 결과는 학생의 모집 카드와 수강 내역에 반영됩니다. 승인은 한 번만 처리하며 이 단계에서 이수 처리나 마일리지 지급은 하지 않습니다.
7. 같은 교육의 신청자 명단에서 **출석 체크박스**를 선택하고 **이수 처리**를 누릅니다. 수강 승인 완료, 출석 체크, 결제 완료 또는 무료 조건이 필요합니다. 체크·해제는 즉시 브라우저에 저장되며 두 관리자 화면에 함께 반영됩니다.
8. **이수 처리**를 누르면 확인 창에서 **이수일자**를 선택합니다. 기본값은 오늘이며 날짜를 비워두면 확정할 수 없습니다. 확정 후 **이수 완료**와 선택한 **이수일**이 표시됩니다. 학생 이수 내역·역량·마일리지(과정당 데모 10점)와 데모 확인서 출력에 반영되며 새로고침 후에도 유지됩니다.
9. 기존 **성과 대시보드 → 출석 / 이수 승인**에서도 동일한 기준으로 처리할 수 있습니다. 두 화면은 같은 이수 기록을 사용합니다.
10. 완료된 학생의 **이수 취소**를 누른 뒤 확인 창에서 **이수 취소 확인**을 선택하면 미이수로 되돌립니다. 출석과 수강 승인은 유지하고, 이수일은 화면에서 숨기며 학생의 완료 건수·역량·마일리지를 재계산합니다. 확인서 신규 발급도 중단됩니다. 다시 이수 처리할 때도 날짜를 선택할 수 있습니다.

여러 학생의 출석을 처리하려면 **전체 출석 처리**를 누르거나, 명단 왼쪽의 **행 선택 체크박스**로 학생을 고른 뒤 **선택 학생 출석 처리 (N명)**를 누르세요. 표 머리글 체크박스로 출석 변경이 가능한 행을 전체 선택·해제할 수 있습니다. 수강 승인된 미이수 학생만 대상이며 수강 미승인·정원 외 대기·이수 완료 행은 선택할 수 없습니다. 이미 출석인 학생은 그대로 유지하고 새로 출석 처리한 인원을 안내합니다. 교육을 변경하거나 일괄 출석 처리가 완료되면 행 선택은 해제됩니다. 출석 변경은 즉시 저장되지만 이수는 자동 처리하지 않습니다.

여러 학생을 한 번에 이수 처리하려면 해당 교육의 출석을 체크한 뒤 **출석자 일괄 이수 처리 (N명)**를 누르세요. 확인 창에서 교육명과 대상 인원을 확인하고 **일괄 이수 확정**을 선택합니다. 선택한 교육의 수강 승인·출석·결제 조건을 충족한 미이수 학생 전체만 처리하며, 다른 교육·미출석·수강 미승인·정원 외 대기·기이수 학생은 제외합니다. 대상이 0명이면 버튼은 비활성화됩니다. 확인 중 대상이 바뀌면 재확인을 요청합니다. 처리 후 학생 기록에 반영되고 개별 이수 취소도 가능합니다.

이수 완료된 기록은 출석 체크가 잠깁니다. 출석을 정정하려면 먼저 이수를 취소하세요. 대기자와 수강 미승인자는 출석을 변경하거나 이수 처리할 수 없습니다. 출석은 현재 교육 단위의 단일 체크이며 회차별 출석부는 아닙니다.

개별·일괄 이수와 기존 대시보드의 이수 승인에 동일한 날짜 선택 창을 사용합니다. 일괄 처리 시 선택한 날짜 하나를 대상 학생 모두에게 적용합니다. 이수일에 교육일·오늘 기준의 추가 제한은 두지 않으므로 실제 이수일을 확인하고 확정하세요.

기존 숫자 출석 기록은 손실 없이 유지하고 80 이상이면 체크 상태로 표시합니다. 체크를 변경하면 내부 호환용 출석 값은 체크 100 / 해제 0으로 저장합니다. 기존 이수 상태는 자동 변경하지 않습니다.

이수 취소는 이미 내려받은 PDF를 회수하거나 작성·저장된 STAR 초안의 문장을 자동 수정하지 않습니다. 취소된 과정의 내용을 포함하는 문서는 직접 검토하고 다시 작성하세요. 취소 시 현재 인쇄용 보고서 내용은 비워 이전 확인서를 다시 출력하지 않도록 합니다.

새로 개설한 교육은 신청자가 없는 상태에서 시작합니다. 초기 모집 과정의 기존 예시 인원은 개별 학생 기록이 없는 집계이므로, 명단의 실제 로컬 신청 기록 수와 다를 수 있으며 화면에 구분해 안내합니다.

**정원 외 대기**는 **수강 승인 대기**와 다릅니다. 정원 외 대기자는 수강 정원을 차지하지 않고 별도 대기 한도에 포함됩니다. 유료 과정도 대기 접수 시 결제하지 않으며, 수강·이수 승인 및 마일리지 지급 대상이 아닙니다. 관리자 명단과 학생 카드·신청 내역에 별도 상태로 표시합니다. 현재는 대기 명단 접수까지만 제공하며, 신청 취소·개설 후 정원 변경·대기자 승격은 지원하지 않습니다.

기존 저장 형식(version 1~6)은 읽을 때 version 7로 변환하고 다음 저장 시 반영합니다. version 6의 회차 교육일은 시작일·종료일이 같은 하루 기간으로 변환하며 회차명·예산·항목 배정·수입·지출을 유지합니다. version 4/5의 프로그램별 예산은 각 프로그램의 **기존 예산** 회차로 이동하며 전체 예산·수입·지출 및 version 5의 항목 배정을 유지합니다. 해당 회차의 시작일·종료일은 기존 프로그램 교육일로 설정하므로 필요하면 수정하세요. version 4의 항목 배정은 0원으로 시작하고 version 1/2/3에는 예산 자료를 빈 상태로 추가합니다. 기존 수강·이수·일지·초안은 유지합니다. version 1/2 교육의 대기자 정원은 0명으로 설정하고 version 3 이후의 기존 대기 한도·명단은 유지합니다. version 1에는 별도 수강 승인 단계가 없었으므로 해당 수강 기록은 수강 승인으로 이어받습니다. 기존에 수집하지 않은 학번·전화번호·이메일은 생성하지 않고 **미등록**으로 표시합니다. 개설 과정과 연결되지 않은 과거 이수 기록은 기존 전체 수강·이수 내역에서 계속 확인할 수 있습니다.

## 프로그램 · 회차별 예산 관리

1. 왼쪽 **예산 · 집행 관리** 메뉴에서 교육을 선택합니다. 기본 화면은 **프로그램 전체 합계 (조회 전용)**입니다.
2. **예산 회차 등록**에서 ‘1회차 기초’, ‘2회차 심화’ 같은 회차명과 **교육 시작일·종료일**을 입력합니다. 두 날짜는 필수이며 종료일은 시작일보다 빠를 수 없습니다. 하루 교육은 같은 날짜를 지정하세요. 신규 회차의 예산·항목 배정·수입·지출은 0원에서 시작하며 등록 후 해당 회차가 선택됩니다.
3. 회차별 **배정 예산**을 입력하고 저장합니다. 회차마다 독립 예산이며 프로그램 공통 한도는 두지 않습니다. 회차 배정 예산은 0~1,000,000,000원의 정수입니다.
4. 선택 회차의 **지출 등록**에서 일자·항목·금액·적요를 입력합니다. 강사비, 교재비, 재료비, 자격 발급비, 운영비, 기타 지출로 분류합니다.
5. 선택 회차의 **교육비 / 수입 등록**에서 실제 수납분을 가정한 가상 수입을 직접 입력합니다. 항목은 학생 교육비, 지원금, 기타 수입입니다. 학생별 개인정보나 결제 수단 정보는 입력하지 마세요.
6. 수입·지출 내역의 **수정**으로 금액·일자·분류·적요를 정정하고, **삭제** 후 확인 창에서 삭제할 수 있습니다. 내역 금액은 1~1,000,000,000원의 정수이며 음수·소수·공백 적요는 허용하지 않습니다. 수정·삭제는 해당 회차에만 반영됩니다.
7. 회차명을 선택한 상태에서 **회차 정보 수정**으로 이름·교육 기간을 변경할 수 있습니다. 동일 프로그램 안에 이름·시작일·종료일이 모두 같은 회차를 중복 등록할 수 없습니다. 회차 선택 목록·현황 표·보고서에도 교육 기간이 표시됩니다. 회차 삭제는 제공하지 않습니다.
8. **프로그램 전체 합계**에서는 회차별 예산 표, 합산 예산·항목 배정·수입·지출을 조회합니다. 입력·수정은 회차를 선택한 뒤에만 할 수 있습니다. 합계의 집행률은 `총 지출 ÷ 총 배정 예산`이며 회차 집행률의 단순 평균이 아닙니다.
9. **예산 보고서 인쇄 / PDF 저장**은 현재 범위를 출력합니다. 회차를 선택하면 해당 회차만, 전체를 선택하면 회차별 표와 전체 내역을 출력합니다. 전체 내역에는 회차명이 표시됩니다. 브라우저 인쇄 창에서 PDF로 저장하세요.

예를 들어 1회차 예산 100만원·지출 40만원, 2회차 예산 200만원·지출 100만원이면 전체 예산 300만원·지출 140만원·집행률 약 46.7%입니다. 전체 잔액에 여유가 있어도 개별 회차는 초과할 수 있으므로 회차별 표를 함께 확인하세요.

예산 회차는 예산 탭 안에서만 사용합니다. 프로그램 개설·신청자·출석·이수는 회차별로 나누지 않습니다. 회차 교육 기간 수정도 기존 프로그램 교육일이나 학생 기록에 영향을 주지 않습니다.

**항목별 배정 예산 · 집행 현황** 표에서 선택 회차의 강사비·교재비·재료비·자격 발급비·운영비·기타 지출 각각의 배정액을 입력하고 **항목별 배정 예산 저장**을 누르세요. 회차 예산은 자동으로 바뀌지 않으며 항목 배정 합계가 해당 회차 예산을 넘으면 저장을 차단합니다. 회차 예산을 기존 항목 배정 합계보다 작게 줄이는 것도 차단하므로, 항목 배정을 먼저 조정하세요. 각 항목은 0~1,000,000,000원의 정수입니다.

- **미배분 예산** = 선택 범위의 배정 예산 − 항목 배정 합계.
- 표에는 저장된 항목 배정액·집행액·잔액·집행률을 표시합니다. 항목 배정액이 0이면 집행률은 산정 불가이며, 지출이 있으면 배정 초과로 표시합니다.
- 항목별 잔액이 음수면 전체 예산에 여유가 있어도 해당 항목에 **배정 초과**를 표시합니다. 초과 지출 자체는 실제 내역을 기록할 수 있도록 차단하지 않습니다.
- 수입은 항목 배정 한도에 포함하지 않습니다. 추가 배정이 필요하면 해당 회차의 배정 예산을 먼저 조정하세요.
- 보고서에도 항목 배정 합계·미배분 예산과 항목별 배정·잔액·집행률을 포함합니다. 입력 후 저장하지 않은 금액은 집계·보고서에 반영하지 않습니다.

집계 기준:

- **예산 잔액** = 배정 예산 − 지출. 수입이 있어도 배정 예산을 초과하면 초과 집행 경고를 표시합니다.
- **수입 포함 가용 잔액** = 배정 예산 + 직접 등록 수입 − 지출.
- **집행률** = 지출 ÷ 배정 예산 × 100. 배정 예산이 0원이면 ‘산정 불가’로 표시합니다. 초과 집행 시 100% 이상도 표시하고, 초과 내역 자체는 기록할 수 있습니다.
- 예: 배정 100만원 / 지출 40만원 / 수입 20만원이면 예산 잔액 60만원, 가용 잔액 80만원, 집행률 40%입니다.
- **데모 신청 교육비 합계**는 프로그램 전체의 ‘데모 완료’ 결제 기록 합계이며 정원 외 대기는 제외합니다. 신청 기록에는 예산 회차가 없으므로 회차별 자료로 배분하지 않습니다. 모든 회차 화면에서 프로그램 참고액으로 표시하며, 이 값을 회차별로 합산하지 마세요. 실제 수입이 아니므로 예산·수입·잔액·집행률에는 합산하지 않습니다. 실제 수납 자료를 해당 회차 수입으로 기록할 때 중복 등록하지 마세요.

금액 변경은 선택한 프로그램의 선택 회차에만 반영되며 새로고침 후에도 유지됩니다. 새로고침하면 기본 조회 범위는 프로그램 전체 합계입니다. 현재 자료는 공식 회계 자료가 아니고 회계 시스템·실제 PG·계좌·영수증과 연동하지 않습니다. 증빙 파일, 세금 계산, 환불·음수 조정 및 감사 이력은 제공하지 않습니다. 잘못 입력한 내역은 수정·삭제로 정정하세요.

## 데이터와 제한 사항

- 통계, 학생 프로필, 기존 이수 기록, 취업 코호트, 일정은 **가상 예시**입니다. 모집 일정도 데모이며 실제 모집기간 검증은 하지 않습니다.
- 이수 인원·자격 취득률·취업률 등의 글로벌 통계 및 과목별 집계는 고정 예시입니다. 신청·승인 시 변경되는 로컬 운영 기록과 별도이며, 실제 운영 통계인 것처럼 합산하지 않습니다. 운영 중인 비교과 수와 예산 집행률은 브라우저에 등록된 자료 기준입니다. 과목군 7개와 최초 모집 과정 4개는 다른 개념입니다.
- 코호트별 행은 조합 이수 그룹의 취업 분포입니다. 그룹 간 학생 중복이 가능하므로 합산할 수 없습니다. 차이는 `%p`로 표기하며 인과관계 또는 통계적 유의성을 주장하지 않습니다.
- 학생 역량 점수는 데모 가중치 모형이며 공식 평가 점수가 아닙니다. 투약 기초 이수로 심화 과정을 완료 처리하지 않습니다.
- 데이터는 해당 브라우저·프로필·파일 위치의 저장 영역에만 남습니다. 파일을 옮기거나 브라우저 데이터를 삭제하면 기존 기록에 접근하지 못할 수 있습니다. 영구 보관·백업·여러 사용자 공유를 보장하지 않습니다.
- 저장 오류 시 상단에 경고하고 기존 저장 내용을 덮어쓰지 않습니다. 다른 탭에서 저장 영역이 바뀌면 현재 탭의 저장을 차단하므로, 작성 내용을 별도로 보관한 후 새로고침하세요.
- 화면 전환은 인증·권한 제어가 아닙니다. 실제 학생·환자 정보, 결제 정보 등 민감한 내용은 입력하지 마세요.
- 입력하지 않은 임상 경험·성과를 자동으로 만들어내지 않습니다. STAR 결과의 `[가이드]` / `[작성 필요]` 부분은 실제 경험에 맞게 직접 작성해야 합니다.
- 포트폴리오는 이수 목록과 실습 기록을 포함하지만 공식 인증서 원본 파일을 첨부하지 않습니다. 병원명 선택은 표제에만 반영되며 병원별 공식 문항과 연동되지 않습니다.
- 출력 기능은 브라우저 인쇄 기능입니다. 직접 PDF 자동 다운로드, 디지털 서명, 위변조 방지 기능은 없습니다.
- CQI 출력물은 **검토용 초안**이며 간호교육인증평가 4주기 공식 서식을 검증한 문서가 아닙니다. 실제 제출 전 기관별 서식과 실제 자료로 검토해야 합니다.
- 이수 확인서는 **데모**로 표시되며 병원 제출용 공식 증명서가 아닙니다.
